## 1-1. モデルカタログ探索（目安 12 分）

| # | 操作 | 画面に表示されるもの | つまずいたら |
|---|---|---|---|
| 1 | 左メニューの「**モデル カタログ**」をクリック | モデルの一覧（検索窓・フィルタ付き） | メニュー名が「Model catalog」等の英語表記の場合はポータルの言語設定（右上 Settings）を日本語に |
| 2 | 検索窓やフィルタで **Meta Llama / Mistral / Cohere / DeepSeek** を探す | OpenAI 以外のモデルカードが並ぶ | 「デプロイにはサブスクリプションが必要」等の表示が出ても**正常**です。今日はデプロイせず、カードを見るだけです |
| 3 | 気になるモデルカードをクリック →「**ベンチマーク**」タブを開く | 品質・速度（レイテンシ／スループット）・コストの比較グラフ | タブ名が「Benchmarks」等の場合あり。カードにベンチマークタブがないモデルもあります（その場合は別モデルで確認） |
| 4 | 下の**課題**に取り組み、記録シートへ記入 | — | 迷ったら講師・助教へ。「正解」はありません。選定**理由**が大事です |

**課題（記録シートの Lab 1 欄へ記入）:**

次の 2 つのユースケースごとに、候補モデルを **2 つずつ**選び、選定理由を
メモしてください。結果は午後の**演習② 研究 AI 評価カード**にも転用します。

- [ ] ユースケース A「**論文要約**」… 候補 2 モデル＋理由
- [ ] ユースケース B「**変異アノテーション解釈**」… 候補 2 モデル＋理由

> **ポイント:** OpenAI 系だけでなく多くのモデルを同じ基盤で比較できる
> 「モデル中立」が Foundry の売りのひとつです。ベンチマークの数値と
> ユースケースの相性を意識して選んでみてください。

## 1-2. Chat Playground（目安 15 分）

| # | 操作 | 画面に表示されるもの | つまずいたら |
|---|---|---|---|
| 1 | 左メニュー「**プレイグラウンド**」→「**チャットのプレイグラウンド**」をクリック | チャット画面（上部にデプロイ選択、右にパラメータパネル） | メニュー構成が違う場合は「Playgrounds」→「Chat」を探す。それでもなければ講師へ |
| 2 | 上部のデプロイ選択ドロップダウンで **gpt-6-luna** を選択 | 選択中のデプロイ名が `gpt-6-luna` に | **ドロップダウンが空**の場合はプロジェクト選択ミスです。左上のプロジェクト名が kirin-rnd-lab か確認 |
| 3 | 「**システムメッセージ**」欄に `あなたはオミックス研究を支援するアシスタントです` と入力し、「**変更を適用**」をクリック | システムメッセージが保存される | **「変更を適用」の押し忘れ**が最多のつまずきです。押さないと反映されません |
| 4 | チャット入力欄に `メタゲノム解析の前処理ステップを教えてください` と入力 → 右端の**送信ボタン** | 回答がストリーミング表示される（QC・ホスト除去等のステップが挙がるはず） | 応答が遅い・エラーになる場合は共有容量の混雑です。少し待って再送信 |
| 5 | 右パネルの **Temperature を 0.2** にして同じ質問を再送信。次に **1.0** にして再送信 | 同じ質問でも回答の揺らぎ方が変わる | 差が分かりにくい場合は 2〜3 回繰り返すか、システムメッセージを消して試す（その効果も観察ポイント） |
| 6 | （余裕があれば）「**Compare**」機能で **gpt-5.6-terra** を追加し、同じ質問を並べて比較 | 2 つのモデルの回答が左右に並ぶ | Compare の入口が見つからない場合は講師の画面共有で確認（時間がなければ省略可） |

**観察ポイント（記録シートの観察メモ欄へ）:**

- [ ] Temperature 0.2（再現性重視）と 1.0（多様性重視）で回答のばらつきが
  どう変わったか
- [ ] 前処理の各ステップ（QC・ホスト除去など）が挙がったか（回答の具体性）
- [ ] システムメッセージを消すと回答がどう変わるか

> **議論のたね:** 研究用途で「同じ入力に同じ出力」が求められる場面では、
> Temperature はどちら側が適切でしょうか。観察結果は**演習②の評価カード**
> に転記します。

## 1-3. 初めての Agent 作成（目安 8 分）

| # | 操作 | 画面に表示されるもの | つまずいたら |
|---|---|---|---|
| 1 | 左メニュー「**エージェント**」→「**＋ 新しいエージェント**」をクリック | エージェント作成画面 | 「エージェント」メニュー自体が見えない場合は講師へ（Lab 0 の Agent Service デプロイ状況を確認します） |
| 2 | 名前に **omics-assistant** と入力 → デプロイのドロップダウンで **gpt-6-luna** を選択 | 名前とデプロイが設定される | デプロイの選択肢が空ならプロジェクト選択ミス（1-2 と同じ対処） |
| 3 | 「**指示（Instructions）**」欄に `あなたはオミックス研究を支援するアシスタントです。実験データの解釈を手伝います` と入力 | 指示文が保存される | — |
| 4 | 「**ツール**」セクションを開き、追加できるツールの一覧を**見るだけ**確認 | Code Interpreter / File Search などの一覧 | **今日はここではツールを追加しません。** 一覧が空・項目名が違う場合もポータルのバージョン差です。実際に Code Interpreter を使うのは **Lab 3** です |
| 5 | 右上「**プレイグラウンドで試す**」をクリック → 1-2 と同じ質問（メタゲノム解析の前処理）を送信 | チャットに似た画面で回答が返る | — |

**確認ポイント（記録シートのチェック欄へ）:**

- [ ] エージェント **omics-assistant** を作成し、ツール一覧を確認した
- [ ] チャットとの違いを説明できる：**指示（Instructions）を保存でき、
  ツールを持たせられる**のがエージェント。チャットは一回きりの会話です

> **Lab 3 への橋渡し:** このエージェントに **Code Interpreter** を持たせると、
> LLM が Python コードを自動生成・実行して変異頻度分析まで自律で行います。
> その仕組みを Lab 3（15:40–16:20）でコードリーディングしながら確認します。
